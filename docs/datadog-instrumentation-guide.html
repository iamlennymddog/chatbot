Datadog instrumentation guide

Step by step: add APM, logs and LLM Observability — with a working Execution Graph for agents, sub-agents and tools — to the BitsTalk Deal Buddy Node.js agent (OpenAI SDK, Claude models).

0How it fits together

The chatbot is a small multi-agent system: Deal Buddy (orchestrator, Claude Sonnet) delegates research to the Deals Specialist sub-agent (Claude Haiku), which calls tools. Both agents use the OpenAI Node.js SDK pointed at Anthropic's OpenAI-compatible endpoint.

Datadog gets the telemetry through two paths:

Node.js backendExpress · OpenAI SDK · agents & tools
dd-traceAPM traces · runtime metrics
log fileJSON logs with trace IDs
OpenTelemetryGenAI spans + span links (OTLP/HTTPS)
Datadog AgentDocker container on the host
DatadogAPM · Logs · LLM Observability
SignalSent byLands in
APM traces, runtime metricsdd-trace → Datadog AgentAPM, service bitstalk-deals-chatbot-api
Logs (correlated to traces)pino JSON file → Datadog AgentLogs
Agent traces, sessions, Execution GraphOpenTelemetry GenAI → Datadog OTLP intakeLLM Observability, ml_app bitstalk-deal-buddy
Why OpenTelemetry for LLM Observability? The Execution Graph draws its edges from span links between spans of the same trace ({from: "output", to: "input"}). The dd-trace Node.js LLM Observability SDK cannot create span links today, so agent, LLM and tool spans are emitted with OpenTelemetry using the GenAI semantic conventions. dd-trace stays in place for APM and logs, with its own LLM Observability switched off to avoid duplicate LLM spans.

2Run the Datadog Agent

The Agent receives APM traces from dd-trace on localhost:8126, DogStatsD metrics on localhost:8125, and tails the backend's log file. The script keeps the API key in a 0600 env file (.dd/datadog.env, gitignored) instead of the docker run command line.

datadog/agent.sh
#!/usr/bin/env bash
# Dedicated Datadog Agent container for the BitsTalk POV (Docker on the laptop, e.g. colima).
# The API key goes into a 0600 env file (.dd/datadog.env), never onto the docker command line.
# Usage: DD_API_KEY=... datadog/agent.sh up | down | status
set -euo pipefail

DIR="$(cd "$(dirname "$0")" && pwd)"
ROOT="$(cd "$DIR/.." && pwd)"
NAME=bitstalk-pov-datadog-agent
ENV_FILE="$ROOT/.dd/datadog.env"

write_env_file() {
  (
    umask 077
    mkdir -p "$ROOT/.dd"
    cat > "$ENV_FILE" <<ENV
DD_API_KEY=${DD_API_KEY}
DD_SITE=${DD_SITE:-datadoghq.com}
DD_ENV=${DD_ENV:-pov}
DD_HOSTNAME=${DD_HOSTNAME:-leendert-meyer-bitstalk-pov}
DD_TAGS=customer:bitstalk project:agent-o11y-pov
DD_APM_ENABLED=true
DD_APM_NON_LOCAL_TRAFFIC=true
DD_DOGSTATSD_NON_LOCAL_TRAFFIC=true
DD_LOGS_ENABLED=true
DD_LOGS_CONFIG_AUTO_MULTI_LINE_DETECTION=true
DD_LOGS_CONFIG_CONTAINER_COLLECT_ALL=false
DD_PROCESS_CONFIG_PROCESS_COLLECTION_ENABLED=false
ENV
  )
  chmod 600 "$ENV_FILE"
}

case "${1:-up}" in
  up)
    : "${DD_API_KEY:?DD_API_KEY must be set}"
    write_env_file
    if docker ps --format '{{.Names}}' | grep -qx "$NAME"; then
      echo "Datadog Agent already running ($NAME)"
      exit 0
    fi
    docker rm -f "$NAME" >/dev/null 2>&1 || true
    docker run -d --name "$NAME" --restart unless-stopped \
      --cgroupns host --pid host \
      --env-file "$ENV_FILE" \
      -p 127.0.0.1:8126:8126/tcp \
      -p 127.0.0.1:8125:8125/udp \
      -v /var/run/docker.sock:/var/run/docker.sock:ro \
      -v /proc/:/host/proc/:ro \
      -v /sys/fs/cgroup/:/host/sys/fs/cgroup:ro \
      -v "$ROOT/backend/logs:/var/log/bitstalk-chatbot:ro" \
      -v "$DIR/conf.d/bitstalk-chatbot.d:/conf.d/bitstalk-chatbot.d:ro" \
      registry.datadoghq.com/agent:7 >/dev/null
    echo "Datadog Agent started ($NAME)"
    ;;
  down)
    docker rm -f "$NAME" >/dev/null 2>&1 && echo "Datadog Agent stopped" || echo "Datadog Agent not running"
    ;;
  status)
    docker exec "$NAME" agent status
    ;;
  *)
    echo "Usage: $0 up|down|status" >&2
    exit 1
    ;;
esac

5Set up OpenTelemetry for LLM Observability

Register an OpenTelemetry tracer provider that exports straight to Datadog's OTLP intake. The endpoint and headers come from environment variables (step 9). service.name becomes the LLM Observability ml_app. Export results are logged, because OpenTelemetry silently drops export errors (wrong key or site) by default.

backend/src/otel.js
// OpenTelemetry GenAI tracing for Datadog LLM Observability (Agent Observability).
//
// Why OTel and not the dd-trace LLM Obs SDK: the Execution Graph draws its edges from span
// links between spans of the same trace, which dd-trace JS cannot emit. OTel can.
//
// - src/agents/runAgent.js creates `invoke_agent`, `chat` and `execute_tool` spans plus the links
//   (the OpenAI SDK has no native OTel instrumentation, so chat spans are created by hand).
// - Export goes straight to Datadog's OTLP intake with LLM Obs conversion enabled
//   (OTEL_EXPORTER_OTLP_TRACES_ENDPOINT / _HEADERS, set by start.sh). service.name -> ml_app.
import { NodeTracerProvider } from '@opentelemetry/sdk-trace-node';
import { BatchSpanProcessor } from '@opentelemetry/sdk-trace-base';
import { resourceFromAttributes } from '@opentelemetry/resources';
import { OTLPTraceExporter as OTLPProtoExporter } from '@opentelemetry/exporter-trace-otlp-proto';
import { OTLPTraceExporter as OTLPJsonExporter } from '@opentelemetry/exporter-trace-otlp-http';
import { logger } from './logger.js';

/** Logs every OTLP export result: OTel swallows exporter errors (bad key, wrong endpoint) by default. */
class LoggingExporter {
  constructor(inner, endpoint) {
    this.inner = inner;
    this.endpoint = endpoint;
  }

  export(spans, resultCallback) {
    this.inner.export(spans, (result) => {
      if (result.code === 0) {
        logger.info({ event: 'otel.export', status: 'ok', spans: spans.length, endpoint: this.endpoint }, 'OTLP export succeeded');
      } else {
        logger.error(
          { event: 'otel.export', status: 'error', spans: spans.length, endpoint: this.endpoint, err: result.error },
          'OTLP export failed',
        );
      }
      resultCallback(result);
    });
  }

  shutdown() {
    return this.inner.shutdown();
  }

  forceFlush() {
    return this.inner.forceFlush?.() ?? Promise.resolve();
  }
}

export const otelEnabled = Boolean(process.env.OTEL_EXPORTER_OTLP_TRACES_ENDPOINT);

const spanProcessors = [];
if (otelEnabled) {
  const json = process.env.OTEL_EXPORTER_OTLP_TRACES_PROTOCOL === 'http/json';
  const exporter = json ? new OTLPJsonExporter() : new OTLPProtoExporter();
  spanProcessors.push(new BatchSpanProcessor(new LoggingExporter(exporter, process.env.OTEL_EXPORTER_OTLP_TRACES_ENDPOINT)));
}

export const provider = new NodeTracerProvider({
  resource: resourceFromAttributes({
    'service.name': process.env.OTEL_SERVICE_NAME || 'bitstalk-deal-buddy',
    'service.version': process.env.DD_VERSION || '1.0.0',
    'deployment.environment.name': process.env.DD_ENV || 'pov',
    dd_llmobs_enabled: true,
  }),
  spanProcessors,
});
provider.register();

export async function shutdownTracing() {
  await provider.shutdown().catch(() => {});
}

Import it first in the entry point, and flush pending spans on shutdown:

6Add GenAI span helpers

Datadog maps the GenAI gen_ai.operation.name attribute to LLM Observability span kinds:

gen_ai.operation.nameLLM Observability span kindUsed for
invoke_agentagenteach agent run (orchestrator and sub-agent)
chatllmeach model call
execute_tooltooleach tool call, including the sub-agent hand-off tool

These helpers create spans, build the {from, to} link objects, and convert OpenAI chat messages to the GenAI message format (role + typed parts: text, tool_call, tool_call_response).

backend/src/tracing.js
// GenAI semantic-convention spans + span links for the LLM Obs Execution Graph.
// Span kinds come from gen_ai.operation.name: invoke_agent -> agent, execute_tool -> tool,
// chat -> llm. Links carry {from, to} to describe data flow between spans of one trace.
import { trace, context, SpanKind, SpanStatusCode } from '@opentelemetry/api';
import { provider } from './otel.js';

const tracer = provider.getTracer('bitstalk-deal-buddy');
const MAX_ATTR = 8000;

export const flow = (spanContext, from, to) => ({ context: spanContext, attributes: { from, to } });
export const json = (value) => {
  const s = typeof value === 'string' ? value : JSON.stringify(value);
  return s.length > MAX_ATTR ? `${s.slice(0, MAX_ATTR)}…` : s;
};

const parseArgs = (args) => {
  try {
    return args ? JSON.parse(args) : {};
  } catch {
    return args;
  }
};

/** OpenAI chat messages -> GenAI semconv messages (role + typed parts). */
export function genAiMessages(messages) {
  return json(
    messages.map((m) => {
      if (m.role === 'tool') {
        return { role: 'tool', parts: [{ type: 'tool_call_response', id: m.tool_call_id, response: m.content }] };
      }
      const parts = [];
      if (m.content) parts.push({ type: 'text', content: String(m.content) });
      for (const tc of m.tool_calls ?? []) {
        parts.push({ type: 'tool_call', id: tc.id, name: tc.function.name, arguments: parseArgs(tc.function.arguments) });
      }
      return { role: m.role, parts, ...(m.finish_reason ? { finish_reason: m.finish_reason } : {}) };
    }),
  );
}

export const activeSpan = () => trace.getSpan(context.active());

/** Run fn inside an active span; records errors and always ends the span. */
export function withSpan(name, { attributes = {}, links = [], kind = SpanKind.INTERNAL } = {}, fn) {
  return tracer.startActiveSpan(name, { attributes, links, kind }, async (span) => {
    try {
      return await fn(span);
    } catch (err) {
      span.recordException(err);
      span.setStatus({ code: SpanStatusCode.ERROR, message: err.message });
      throw err;
    } finally {
      span.end();
    }
  });
}

export { SpanKind, SpanStatusCode };

7b. LLM span

The OpenAI SDK does not emit OpenTelemetry spans itself, so wrap each Chat Completions call in a chat span with the request, response, token usage and messages:

backend/src/agents/runAgent.js — chat
/** One Chat Completions call inside a GenAI `chat` span (the OpenAI SDK has no native OTel spans). */
function chat({ model, maxTokens, convo, toolDefs, systemInstructions, toolDefinitions, ctx, links }) {
  return withSpan(
    `chat ${model}`,
    {
      kind: SpanKind.CLIENT,
      attributes: {
        'gen_ai.operation.name': 'chat',
        'gen_ai.provider.name': PROVIDER,
        'gen_ai.request.model': model,
        'gen_ai.request.max_tokens': maxTokens,
        'gen_ai.conversation.id': ctx.sessionId,
        'gen_ai.system_instructions': systemInstructions,
        'gen_ai.tool.definitions': toolDefinitions,
        'gen_ai.input.messages': genAiMessages(convo.filter((m) => m.role !== 'system')),
      },
      links,
    },
    async (span) => {
      const response = await openai.chat.completions.create({ model, max_tokens: maxTokens, messages: convo, tools: toolDefs });
      const choice = response.choices[0];
      span.setAttributes({
        'gen_ai.response.id': response.id,
        'gen_ai.response.model': response.model,
        'gen_ai.response.finish_reasons': [choice.finish_reason],
        'gen_ai.usage.input_tokens': response.usage?.prompt_tokens ?? 0,
        'gen_ai.usage.output_tokens': response.usage?.completion_tokens ?? 0,
        'gen_ai.output.messages': genAiMessages([{ ...choice.message, finish_reason: choice.finish_reason }]),
      });
      return { response, choice, chatSpan: span.spanContext() };
    },
  );
}

Show the complete runAgent.js
backend/src/agents/runAgent.js
import { openai } from './client.js';
import { withSpan, flow, json, genAiMessages, activeSpan, SpanKind, SpanStatusCode } from '../tracing.js';

const MAX_ITERATIONS = 6;
const PROVIDER = 'anthropic'; // OpenAI SDK -> Anthropic's OpenAI-compatible endpoint

/**
 * Generic tool-use loop on the OpenAI Chat Completions API, traced with OTel GenAI conventions.
 * tools: [{ definition: {name, description, input_schema}, handler: async (input, ctx) => any }]
 * ctx:   { log, sessionId, steps, sources } shared across the whole request (all agents).
 *
 * Execution Graph edges (span links, all in one trace):
 *   caller tool --input->input--> agent --input->input--> first chat
 *   chat --output->input--> each tool it called --output->input--> next chat
 *   last chat --output->output--> agent --output->output--> caller tool
 */
export async function runAgent({ name, description, model, system, messages, tools, ctx, maxTokens = 1024 }) {
  const toolMap = new Map(tools.map((t) => [t.definition.name, t]));
  const caller = activeSpan(); // set when this agent is invoked from a tool (sub-agent)
  const toolDefs = tools.map((t) => ({
    type: 'function',
    function: { name: t.definition.name, description: t.definition.description, parameters: t.definition.input_schema },
  }));
  const systemInstructions = json([{ type: 'text', content: system }]);
  const toolDefinitions = json(
    tools.map((t) => ({
      type: 'function',
      name: t.definition.name,
      description: t.definition.description,
      parameters: t.definition.input_schema,
    })),
  );

  return withSpan(
    `invoke_agent ${name}`,
    {
      attributes: {
        'gen_ai.operation.name': 'invoke_agent',
        'gen_ai.provider.name': PROVIDER,
        'gen_ai.agent.name': name,
        'gen_ai.agent.description': description,
        'gen_ai.request.model': model,
        'gen_ai.request.max_tokens': maxTokens,
        'gen_ai.conversation.id': ctx.sessionId,
        'gen_ai.system_instructions': systemInstructions,
        'gen_ai.tool.definitions': toolDefinitions,
        'gen_ai.input.messages': genAiMessages(messages.slice(-1)),
      },
      links: caller ? [flow(caller.spanContext(), 'input', 'input')] : [],
    },
    async (agentSpan) => {
      const log = ctx.log.child({ agent: name, otel_trace_id: agentSpan.spanContext().traceId });
      const convo = [{ role: 'system', content: system }, ...messages];
      const usage = { input_tokens: 0, output_tokens: 0 };
      log.info({ event: 'agent.start', model }, `Agent ${name} started`);

      // The first LLM call consumes the agent's input; later ones consume the tool results.
      let chatInputs = [flow(agentSpan.spanContext(), 'input', 'input')];
      let lastChat = null;

      const finish = (text, iterations) => {
        if (lastChat) agentSpan.addLink(flow(lastChat, 'output', 'output'));
        if (caller) caller.addLink(flow(agentSpan.spanContext(), 'output', 'output'));
        agentSpan.setAttributes({
          'gen_ai.output.messages': json([{ role: 'assistant', parts: [{ type: 'text', content: text }], finish_reason: 'stop' }]),
          'gen_ai.usage.input_tokens': usage.input_tokens,
          'gen_ai.usage.output_tokens': usage.output_tokens,
        });
        return { text, usage, iterations };
      };

      for (let i = 1; i <= MAX_ITERATIONS; i++) {
        const t0 = Date.now();
        const { response, choice, chatSpan } = await chat({ model, maxTokens, convo, toolDefs, systemInstructions, toolDefinitions, ctx, links: chatInputs });
        lastChat = chatSpan;
        usage.input_tokens += response.usage?.prompt_tokens ?? 0;
        usage.output_tokens += response.usage?.completion_tokens ?? 0;
        log.info(
          {
            event: 'agent.llm_call',
            model: response.model,
            iteration: i,
            llm_ms: Date.now() - t0,
            stop_reason: choice.finish_reason,
            input_tokens: response.usage?.prompt_tokens,
            output_tokens: response.usage?.completion_tokens,
          },
          `Agent ${name} LLM call ${i}`,
        );

        const toolCalls = choice.message.tool_calls ?? [];
        if (choice.finish_reason !== 'tool_calls' || toolCalls.length === 0) {
          const text = choice.message.content ?? '';
          log.info({ event: 'agent.end', iterations: i, ...usage }, `Agent ${name} finished`);
          return finish(text, i);
        }

        convo.push(choice.message);
        const outcomes = await Promise.all(toolCalls.map((tc) => executeTool(tc, toolMap, ctx, log, name, chatSpan)));
        convo.push(...outcomes.map((o) => o.result));
        // Every tool result feeds the next LLM call.
        chatInputs = outcomes.map((o) => flow(o.spanContext, 'output', 'input'));
      }

      log.warn({ event: 'agent.max_iterations', ...usage }, `Agent ${name} hit max iterations`);
      return finish("Sorry, I couldn't complete that request. Please try rephrasing.", MAX_ITERATIONS);
    },
  );
}

    },
    async (span) => {
      const response = await openai.chat.completions.create({ model, max_tokens: maxTokens, messages: convo, tools: toolDefs });
      const choice = response.choices[0];
      span.setAttributes({
        'gen_ai.response.id': response.id,
        'gen_ai.response.model': response.model,
        'gen_ai.response.finish_reasons': [choice.finish_reason],
        'gen_ai.usage.input_tokens': response.usage?.prompt_tokens ?? 0,
        'gen_ai.usage.output_tokens': response.usage?.completion_tokens ?? 0,
        'gen_ai.output.messages': genAiMessages([{ ...choice.message, finish_reason: choice.finish_reason }]),
      });
      return { response, choice, chatSpan: span.spanContext() };
    },
  );
}

async function executeTool(toolCall, toolMap, ctx, log, agentName, chatSpan) {
  const toolUse = { id: toolCall.id, name: toolCall.function.name, input: parseArgs(toolCall.function.arguments) };
  const tool = toolMap.get(toolUse.name);
  const t0 = Date.now();
  ctx.steps.push({ agent: agentName, tool: toolUse.name, input: toolUse.input });

  return withSpan(
    `execute_tool ${toolUse.name}`,
    {
      attributes: {
        'gen_ai.operation.name': 'execute_tool',
        'gen_ai.tool.name': toolUse.name,
        'gen_ai.tool.type': 'function',
        'gen_ai.tool.call.id': toolUse.id,
        'gen_ai.tool.description': tool?.definition.description,
        'gen_ai.tool.call.arguments': json(toolUse.input),
      },
      // The LLM's tool call output is this tool's input.
      links: chatSpan ? [flow(chatSpan, 'output', 'input')] : [],
    },
    async (span) => {
      const spanContext = span.spanContext();
      try {
        if (!tool) throw new Error(`Unknown tool ${toolUse.name}`);
        const output = await tool.handler(toolUse.input, ctx);
        const content = typeof output === 'string' ? output : JSON.stringify(output);
        span.setAttribute('gen_ai.tool.call.result', json(content));
        log.info(
          { event: 'tool.call', tool: toolUse.name, tool_input: toolUse.input, tool_ms: Date.now() - t0, status: 'ok' },
          `Tool ${toolUse.name} executed`,
        );
        return { spanContext, result: { role: 'tool', tool_call_id: toolUse.id, content } };
      } catch (err) {
        // Tool errors go back to the model as text, so record them without failing the request.
        span.recordException(err);
        span.setStatus({ code: SpanStatusCode.ERROR, message: err.message });
        log.error({ event: 'tool.call', tool: toolUse.name, tool_input: toolUse.input, status: 'error', err }, `Tool ${toolUse.name} failed`);
        return { spanContext, result: { role: 'tool', tool_call_id: toolUse.id, content: `Error: ${err.message}` } };
      }
    },
  );
}

function parseArgs(args) {
  try {
    return args ? JSON.parse(args) : {};
  } catch {
    return {};
  }
}

Stop the stack

stop.sh stops the backend and frontend, then the Datadog Agent container. The backend gets SIGTERM first, so pending OpenTelemetry spans are flushed to Datadog before it exits. Use --keep-agent to stop only the app, which is what Ctrl+C in the start.sh terminal does too.

Shell
./stop.sh               # stop backend, frontend and the Datadog Agent
./stop.sh --keep-agent  # stop the app, leave the Agent running
Show stop.sh
stop.sh
#!/usr/bin/env bash
# Stops BitsTalk Deal Buddy: backend (:3001), frontend (:5173) and the Datadog Agent container.
# Usage: ./stop.sh               stop everything
#        ./stop.sh --keep-agent  stop the app, leave the Datadog Agent running
set -euo pipefail

ROOT="$(cd "$(dirname "$0")" && pwd)"
KEEP_AGENT=0
[[ "${1:-}" == "--keep-agent" ]] && KEEP_AGENT=1

# Sends SIGTERM to whatever listens on the port (the backend flushes pending OTel spans on SIGTERM), waits up to 5s, then SIGKILLs.
stop_port() {
  local name="$1" port="$2" pids
  pids="$(lsof -ti "tcp:${port}" -sTCP:LISTEN 2>/dev/null || true)"
  if [[ -z "$pids" ]]; then
    echo "${name}: not running"
    return
  fi
  kill $pids 2>/dev/null || true
  for _ in $(seq 1 10); do
    lsof -ti "tcp:${port}" -sTCP:LISTEN >/dev/null 2>&1 || { echo "${name}: stopped"; return; }
    sleep 0.5
  done
  kill -9 $(lsof -ti "tcp:${port}" -sTCP:LISTEN 2>/dev/null) 2>/dev/null || true
  echo "${name}: force-stopped"
}

stop_port "Backend  (:${PORT:-3001})" "${PORT:-3001}"
stop_port "Frontend (:5173)" 5173

if [[ "$KEEP_AGENT" == 1 ]]; then
  echo "Datadog Agent: left running (stop it later with ./stop.sh or datadog/agent.sh down)"
elif docker info >/dev/null 2>&1; then
  printf 'Datadog Agent: '
  "$ROOT/datadog/agent.sh" down
else
  echo "Datadog Agent: Docker is not running, nothing to stop"
fi

11Troubleshooting

SymptomCause and fix
No traces in LLM ObservabilityCheck grep otel.export backend/logs/app.log. status: error with 401/403 means a wrong API key or the wrong DD_SITE (the OTLP host is otlp.<site>).
Traces appear but there is no Execution Graph buttonThe spans have no links. Make sure LLM Observability comes from OpenTelemetry (steps 5–7), not from dd-trace's DD_LLMOBS_ENABLED.
Every model call appears twiceBoth dd-trace LLM Observability and OpenTelemetry are on. Unset DD_LLMOBS_ENABLED.
Each turn is its own sessionThe frontend must reuse one sessionId per conversation; the backend sets it as gen_ai.conversation.id.
No APM tracesStart the backend with node --import dd-trace/initialize.mjs and check the Agent: curl localhost:8126/info.
Logs not linked to tracesSet DD_LOGS_INJECTION=true, and make sure the Agent's log config uses the same service as DD_SERVICE.
