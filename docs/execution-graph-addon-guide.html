Add the Execution Graph to an existing dd-trace agent

For Node.js agents that already send APM traces and logs to Datadog with dd-trace: keep that setup and add LLM Observability's Execution Graph with OpenTelemetry GenAI spans.

0Before you start

This guide is for a Node.js agent that already sends APM traces and logs to Datadog with dd-trace, but has no Execution Graph in LLM Observability. It adds the graph on top, without touching the APM and log setup.

Stays as it isChanges
  • dd-trace, loaded with --import dd-trace/initialize.mjs
  • The Datadog Agent, APM traces, runtime metrics
  • Log collection and log/trace correlation
  • Your LLM client, tools and agent logic
  • dd-trace's own LLM Observability is switched off
  • LLM Observability spans come from OpenTelemetry instead, sent straight to Datadog's OTLP intake
  • Two small files are added (otel.js, tracing.js)
  • Your agent loop gets three kinds of spans and the links between them
Why the switch? The Execution Graph draws its edges from span links between spans of the same trace, each link saying how data flowed ({from: "output", to: "input"}). The dd-trace Node.js LLM Observability SDK cannot create span links today; OpenTelemetry can. dd-trace stays in place for everything else. Datadog docs: OpenTelemetry Instrumentation → Span links.

Trade-offs to know about

  • No tracer.llmobs APIs. With dd-trace's LLM Observability off, llmobs.trace(), llmobs.annotate() and prompt management (tracer.llmobs.prompts.getPrompt) can't be used. Prompt tracking still works through an OpenTelemetry attribute (see step 6).
  • LLM spans are created by hand. The OpenAI Node.js SDK emits no OpenTelemetry spans, so each model call is wrapped in a span (step 5). APM's automatic openai.request spans are unaffected.
  • Slower to appear. Spans sent over OTLP took 3–4 minutes to become searchable in LLM Observability in our tests, against about one minute for APM and logs.

The working reference is this repository's main branch: backend/src/otel.js, backend/src/tracing.js and backend/src/agents/runAgent.js. The full guide, docs/datadog-instrumentation-guide.html, covers the same code with more detail.

1Switch dd-trace's LLM Observability off

Remove DD_LLMOBS_ENABLED (and DD_LLMOBS_ML_APP, DD_LLMOBS_AGENTLESS_ENABLED) from the app's environment, wherever it is set: shell scripts, Dockerfile, Helm values, Kubernetes manifests. If both dd-trace and OpenTelemetry send LLM Observability data, every model call appears twice.

If your code calls llmobs.trace(), llmobs.wrap() or llmobs.annotate(), replace those calls with the OpenTelemetry spans from step 5. They are the same places in your code: the agent run, each tool and each model call.

Leave everything else in dd-trace alone. APM, the OpenAI integration's APM spans and DD_LOGS_INJECTION keep working with LLM Observability off.

3Add the OpenTelemetry setup

Copy backend/src/otel.js into your app unchanged. It:

  • registers an OpenTelemetry tracer provider that exports to the OTLP endpoint from the environment (step 7),
  • gives each LLM Observability trace the same trace ID as the dd-trace request, so View in APM and log correlation work from LLM Observability,
  • logs every export result, because OpenTelemetry silently drops export errors (wrong key or site) by default.

It uses the app's logger (./logger.js). Point that import at your own logger, or replace the logger.info / logger.error calls with console.

Show otel.js
backend/src/otel.js
// OpenTelemetry GenAI tracing for Datadog LLM Observability (Agent Observability).
//
// Why OTel and not the dd-trace LLM Obs SDK: the Execution Graph draws its edges from span
// links between spans of the same trace, which dd-trace JS cannot emit. OTel can.
//
// - src/agents/runAgent.js creates `invoke_agent`, `chat` and `execute_tool` spans plus the links
//   (the OpenAI SDK has no native OTel instrumentation, so chat spans are created by hand).
// - Export goes straight to Datadog's OTLP intake with LLM Obs conversion enabled
//   (OTEL_EXPORTER_OTLP_TRACES_ENDPOINT / _HEADERS, set by start.sh). service.name -> ml_app.
// - LLM Obs traces reuse the dd-trace (APM) trace ID of the current request, so a trace opened in
//   LLM Observability links to its APM trace ("View in APM") and to the correlated logs.
import ddTracer from 'dd-trace';
import { NodeTracerProvider } from '@opentelemetry/sdk-trace-node';
import { BatchSpanProcessor, RandomIdGenerator } from '@opentelemetry/sdk-trace-base';
import { resourceFromAttributes } from '@opentelemetry/resources';
import { OTLPTraceExporter as OTLPProtoExporter } from '@opentelemetry/exporter-trace-otlp-proto';
import { OTLPTraceExporter as OTLPJsonExporter } from '@opentelemetry/exporter-trace-otlp-http';
import { logger } from './logger.js';

/**
 * New OTel traces take the 128-bit trace ID of the active dd-trace span (the HTTP request), which is
 * also the dd.trace_id injected into every log line. Falls back to a random ID outside a request or
 * when dd-trace isn't loaded.
 */
class DatadogTraceIdGenerator {
  #random = new RandomIdGenerator();

  generateTraceId() {
    const ddContext = ddTracer.scope().active()?.context();
    return ddContext ? ddContext.toTraceId(true) : this.#random.generateTraceId();
  }

  generateSpanId() {
    return this.#random.generateSpanId();
  }
}

/** Logs every OTLP export result: OTel swallows exporter errors (bad key, wrong endpoint) by default. */
class LoggingExporter {
  constructor(inner, endpoint) {
    this.inner = inner;
    this.endpoint = endpoint;
  }

  export(spans, resultCallback) {
    this.inner.export(spans, (result) => {
      if (result.code === 0) {
        logger.info({ event: 'otel.export', status: 'ok', spans: spans.length, endpoint: this.endpoint }, 'OTLP export succeeded');
      } else {
        logger.error(
          { event: 'otel.export', status: 'error', spans: spans.length, endpoint: this.endpoint, err: result.error },
          'OTLP export failed',
        );
      }
      resultCallback(result);
    });
  }

  shutdown() {
    return this.inner.shutdown();
  }

  forceFlush() {
    return this.inner.forceFlush?.() ?? Promise.resolve();
  }
}

export const otelEnabled = Boolean(process.env.OTEL_EXPORTER_OTLP_TRACES_ENDPOINT);

const spanProcessors = [];
if (otelEnabled) {
  const json = process.env.OTEL_EXPORTER_OTLP_TRACES_PROTOCOL === 'http/json';
  const exporter = json ? new OTLPJsonExporter() : new OTLPProtoExporter();
  spanProcessors.push(new BatchSpanProcessor(new LoggingExporter(exporter, process.env.OTEL_EXPORTER_OTLP_TRACES_ENDPOINT)));
}

export const provider = new NodeTracerProvider({
  idGenerator: new DatadogTraceIdGenerator(),
  resource: resourceFromAttributes({
    'service.name': process.env.OTEL_SERVICE_NAME || 'bitstalk-deal-buddy',
    'service.version': process.env.DD_VERSION || '1.0.0',
    'deployment.environment.name': process.env.DD_ENV || 'pov',
    dd_llmobs_enabled: true,
  }),
  spanProcessors,
});
provider.register();

export async function shutdownTracing() {
  await provider.shutdown().catch(() => {});
}

Import it first in your entry point and flush on shutdown, so the last spans are not lost when the process stops:

Your entry point
// your entry point (server.js / index.js)
import { shutdownTracing } from './otel.js';   // first application import
// ... the rest of your imports and app

for (const signal of ['SIGINT', 'SIGTERM']) {
  process.once(signal, async () => {
    await shutdownTracing();                    // flush pending LLM Observability spans
    process.exit(0);
  });
}

Show tracing.js
backend/src/tracing.js
// GenAI semantic-convention spans + span links for the LLM Obs Execution Graph.
// Span kinds come from gen_ai.operation.name: invoke_agent -> agent, execute_tool -> tool,
// chat -> llm. Links carry {from, to} to describe data flow between spans of one trace.
import { trace, context, SpanKind, SpanStatusCode } from '@opentelemetry/api';
import { provider } from './otel.js';

const tracer = provider.getTracer('bitstalk-deal-buddy');
const MAX_ATTR = 8000;

export const flow = (spanContext, from, to) => ({ context: spanContext, attributes: { from, to } });
export const json = (value) => {
  const s = typeof value === 'string' ? value : JSON.stringify(value);
  return s.length > MAX_ATTR ? `${s.slice(0, MAX_ATTR)}…` : s;
};

const parseArgs = (args) => {
  try {
    return args ? JSON.parse(args) : {};
  } catch {
    return args;
  }
};

/** OpenAI chat messages -> GenAI semconv messages (role + typed parts). */
export function genAiMessages(messages) {
  return json(
    messages.map((m) => {
      if (m.role === 'tool') {
        return { role: 'tool', parts: [{ type: 'tool_call_response', id: m.tool_call_id, response: m.content }] };
      }
      const parts = [];
      if (m.content) parts.push({ type: 'text', content: String(m.content) });
      for (const tc of m.tool_calls ?? []) {
        parts.push({ type: 'tool_call', id: tc.id, name: tc.function.name, arguments: parseArgs(tc.function.arguments) });
      }
      return { role: m.role, parts, ...(m.finish_reason ? { finish_reason: m.finish_reason } : {}) };
    }),
  );
}

export const activeSpan = () => trace.getSpan(context.active());

/** Run fn inside an active span; records errors and always ends the span. */
export function withSpan(name, { attributes = {}, links = [], kind = SpanKind.INTERNAL } = {}, fn) {
  return tracer.startActiveSpan(name, { attributes, links, kind }, async (span) => {
    try {
      return await fn(span);
    } catch (err) {
      span.recordException(err);
      span.setStatus({ code: SpanStatusCode.ERROR, message: err.message });
      throw err;
    } finally {
      span.end();
    }
  });
}

export { SpanKind, SpanStatusCode };

5Instrument the agent loop

This is the only step that touches your agent code. Datadog maps gen_ai.operation.name to the LLM Observability span kind, so you need three kinds of spans:

Spangen_ai.operation.nameWraps
agentinvoke_agentone agent run (orchestrator or sub-agent)
llmchatone model call
toolexecute_toolone tool call, including a tool that hands off to a sub-agent

And these links, which become the graph's edges. Links are drawn only between spans of the same trace, and carry from / to attributes (Datadog docs: Span links):

LinkPut it on
agent input → input first model callthe first chat span
model call output → input tool it requestedeach execute_tool span
tool output → input next model callthe next chat span (one link per tool)
last model call output → output agentthe invoke_agent span, when the agent finishes
hand-off tool input → input sub-agent, and sub-agent output → output hand-off toolthe sub-agent's invoke_agent span, and the hand-off tool span

A typical tool-use loop with all of this in place looks like the sketch below. Only the withSpan wrappers and links are new; callYourModel and runYourTool stand for code you already have.

Sketch: your agent loop with spans and links
import { withSpan, flow, json, genAiMessages, activeSpan, SpanKind } from './tracing.js';

export async function runAgent({ name, model, messages, tools, sessionId }) {
  const caller = activeSpan(); // the hand-off tool's span when this agent runs as a sub-agent

  // 1. Agent span. A sub-agent links its input to the tool that called it.
  return withSpan(`invoke_agent ${name}`, {
    attributes: {
      'gen_ai.operation.name': 'invoke_agent',
      'gen_ai.agent.name': name,
      'gen_ai.conversation.id': sessionId,
      'gen_ai.input.messages': genAiMessages(messages.slice(-1)),
    },
    links: caller ? [flow(caller.spanContext(), 'input', 'input')] : [],
  }, async (agentSpan) => {
    let inputs = [flow(agentSpan.spanContext(), 'input', 'input')]; // first model call reads the agent input

    while (true) {
      // 2. LLM span around YOUR existing model call, linked to whatever fed it.
      const { message, chatSpan } = await withSpan(`chat ${model}`, {
        kind: SpanKind.CLIENT,
        attributes: {
          'gen_ai.operation.name': 'chat',
          'gen_ai.request.model': model,
          'gen_ai.conversation.id': sessionId,
          'gen_ai.input.messages': genAiMessages(messages),
        },
        links: inputs,
      }, async (span) => {
        const response = await callYourModel(messages, tools);           // unchanged
        const message = response.choices[0].message;
        span.setAttributes({
          'gen_ai.usage.input_tokens': response.usage?.prompt_tokens ?? 0,
          'gen_ai.usage.output_tokens': response.usage?.completion_tokens ?? 0,
          'gen_ai.output.messages': genAiMessages([message]),
        });
        return { message, chatSpan: span.spanContext() };
      });

      // 4. Done: the last model call's output is the agent's output (and the caller tool's output).
      if (!message.tool_calls?.length) {
        agentSpan.addLink(flow(chatSpan, 'output', 'output'));
        caller?.addLink(flow(agentSpan.spanContext(), 'output', 'output'));
        agentSpan.setAttribute('gen_ai.output.messages', genAiMessages([message]));
        return message.content;
      }

      // 3. Tool spans, each linked to the model call that requested it.
      messages.push(message);
      const results = await Promise.all(message.tool_calls.map((tc) =>
        withSpan(`execute_tool ${tc.function.name}`, {
          attributes: {
            'gen_ai.operation.name': 'execute_tool',
            'gen_ai.tool.name': tc.function.name,
            'gen_ai.tool.call.id': tc.id,
            'gen_ai.tool.call.arguments': tc.function.arguments,
          },
          links: [flow(chatSpan, 'output', 'input')],
        }, async (span) => {
          const content = await runYourTool(tc);                         // unchanged; may call runAgent()
          span.setAttribute('gen_ai.tool.call.result', json(content));
          return { spanContext: span.spanContext(), reply: { role: 'tool', tool_call_id: tc.id, content } };
        })));

      messages.push(...results.map((r) => r.reply));
      inputs = results.map((r) => flow(r.spanContext, 'output', 'input')); // tool results feed the next call
    }
  });
}
Sub-agents need no extra code. When a tool handler calls runAgent(), activeSpan() returns that tool's span, so the sub-agent links itself to its caller in both directions. Because withSpan uses active spans, everything stays in one trace.

The complete version in this repository adds model and provider names, the system prompt, tool definitions, token usage on the agent span, error handling and logging:

Show backend/src/agents/runAgent.js
backend/src/agents/runAgent.js
import { openai } from './client.js';
import { withSpan, flow, json, genAiMessages, activeSpan, SpanKind, SpanStatusCode } from '../tracing.js';
import { promptTracking } from './prompts.js';

const MAX_ITERATIONS = 6;
const PROVIDER = 'anthropic'; // OpenAI SDK -> Anthropic's OpenAI-compatible endpoint

/**
 * Generic tool-use loop on the OpenAI Chat Completions API, traced with OTel GenAI conventions.
 * tools: [{ definition: {name, description, input_schema}, handler: async (input, ctx) => any }]
 * ctx:   { log, sessionId, steps, sources } shared across the whole request (all agents).
 * prompt: { id, version, template, variables } of the system prompt, for LLM Obs prompt tracking.
 *
 * Execution Graph edges (span links, all in one trace):
 *   caller tool --input->input--> agent --input->input--> first chat
 *   chat --output->input--> each tool it called --output->input--> next chat
 *   last chat --output->output--> agent --output->output--> caller tool
 */
export async function runAgent({ name, description, model, system, prompt, messages, tools, ctx, maxTokens = 1024 }) {
  const toolMap = new Map(tools.map((t) => [t.definition.name, t]));
  const caller = activeSpan(); // set when this agent is invoked from a tool (sub-agent)
  const toolDefs = tools.map((t) => ({
    type: 'function',
    function: { name: t.definition.name, description: t.definition.description, parameters: t.definition.input_schema },
  }));
  const systemInstructions = json([{ type: 'text', content: system }]);
  // Same prompt metadata on every LLM call of this agent run; the user message is the agent's input.
  const promptAttr = prompt ? promptTracking(prompt, messages.at(-1)?.content) : undefined;
  const toolDefinitions = json(
    tools.map((t) => ({
      type: 'function',
      name: t.definition.name,
      description: t.definition.description,
      parameters: t.definition.input_schema,
    })),
  );

  return withSpan(
    `invoke_agent ${name}`,
    {
      attributes: {
        'gen_ai.operation.name': 'invoke_agent',
        'gen_ai.provider.name': PROVIDER,
        'gen_ai.agent.name': name,
        'gen_ai.agent.description': description,
        'gen_ai.request.model': model,
        'gen_ai.request.max_tokens': maxTokens,
        'gen_ai.conversation.id': ctx.sessionId,
        'gen_ai.system_instructions': systemInstructions,
        'gen_ai.tool.definitions': toolDefinitions,
        'gen_ai.input.messages': genAiMessages(messages.slice(-1)),
      },
      links: caller ? [flow(caller.spanContext(), 'input', 'input')] : [],
    },
    async (agentSpan) => {
      const log = ctx.log.child({ agent: name, otel_trace_id: agentSpan.spanContext().traceId });
      const convo = [{ role: 'system', content: system }, ...messages];
      const usage = { input_tokens: 0, output_tokens: 0 };
      log.info({ event: 'agent.start', model }, `Agent ${name} started`);

      // The first LLM call consumes the agent's input; later ones consume the tool results.
      let chatInputs = [flow(agentSpan.spanContext(), 'input', 'input')];
      let lastChat = null;

      const finish = (text, iterations) => {
        if (lastChat) agentSpan.addLink(flow(lastChat, 'output', 'output'));
        if (caller) caller.addLink(flow(agentSpan.spanContext(), 'output', 'output'));
        agentSpan.setAttributes({
          'gen_ai.output.messages': json([{ role: 'assistant', parts: [{ type: 'text', content: text }], finish_reason: 'stop' }]),
          'gen_ai.usage.input_tokens': usage.input_tokens,
          'gen_ai.usage.output_tokens': usage.output_tokens,
        });
        return { text, usage, iterations };
      };

      for (let i = 1; i <= MAX_ITERATIONS; i++) {
        const t0 = Date.now();
        const { response, choice, chatSpan } = await chat({ model, maxTokens, convo, toolDefs, systemInstructions, toolDefinitions, promptAttr, ctx, links: chatInputs });
        lastChat = chatSpan;
        usage.input_tokens += response.usage?.prompt_tokens ?? 0;
        usage.output_tokens += response.usage?.completion_tokens ?? 0;
        log.info(
          {
            event: 'agent.llm_call',
            model: response.model,
            iteration: i,
            llm_ms: Date.now() - t0,
            stop_reason: choice.finish_reason,
            input_tokens: response.usage?.prompt_tokens,
            output_tokens: response.usage?.completion_tokens,
          },
          `Agent ${name} LLM call ${i}`,
        );

        const toolCalls = choice.message.tool_calls ?? [];
        if (choice.finish_reason !== 'tool_calls' || toolCalls.length === 0) {
          const text = choice.message.content ?? '';
          log.info({ event: 'agent.end', iterations: i, ...usage }, `Agent ${name} finished`);
          return finish(text, i);
        }

        convo.push(choice.message);
        const outcomes = await Promise.all(toolCalls.map((tc) => executeTool(tc, toolMap, ctx, log, name, chatSpan)));
        convo.push(...outcomes.map((o) => o.result));
        // Every tool result feeds the next LLM call.
        chatInputs = outcomes.map((o) => flow(o.spanContext, 'output', 'input'));
      }

      log.warn({ event: 'agent.max_iterations', ...usage }, `Agent ${name} hit max iterations`);
      return finish("Sorry, I couldn't complete that request. Please try rephrasing.", MAX_ITERATIONS);
    },
  );
}

/** One Chat Completions call inside a GenAI `chat` span (the OpenAI SDK has no native OTel spans). */
function chat({ model, maxTokens, convo, toolDefs, systemInstructions, toolDefinitions, promptAttr, ctx, links }) {
  return withSpan(
    `chat ${model}`,
    {
      kind: SpanKind.CLIENT,
      attributes: {
        'gen_ai.operation.name': 'chat',
        'gen_ai.provider.name': PROVIDER,
        'gen_ai.request.model': model,
        'gen_ai.request.max_tokens': maxTokens,
        'gen_ai.conversation.id': ctx.sessionId,
        'gen_ai.system_instructions': systemInstructions,
        'gen_ai.tool.definitions': toolDefinitions,
        'gen_ai.input.messages': genAiMessages(convo.filter((m) => m.role !== 'system')),
        // Prompt tracking (id, version, template, variables); only read on LLM spans.
        ...(promptAttr ? { '_dd.ml_obs.prompt_tracking': promptAttr } : {}),
      },
      links,
    },
    async (span) => {
      const response = await openai.chat.completions.create({ model, max_tokens: maxTokens, messages: convo, tools: toolDefs });
      const choice = response.choices[0];
      span.setAttributes({
        'gen_ai.response.id': response.id,
        'gen_ai.response.model': response.model,
        'gen_ai.response.finish_reasons': [choice.finish_reason],
        'gen_ai.usage.input_tokens': response.usage?.prompt_tokens ?? 0,
        'gen_ai.usage.output_tokens': response.usage?.completion_tokens ?? 0,
        'gen_ai.output.messages': genAiMessages([{ ...choice.message, finish_reason: choice.finish_reason }]),
      });
      return { response, choice, chatSpan: span.spanContext() };
    },
  );
}

async function executeTool(toolCall, toolMap, ctx, log, agentName, chatSpan) {
  const toolUse = { id: toolCall.id, name: toolCall.function.name, input: parseArgs(toolCall.function.arguments) };
  const tool = toolMap.get(toolUse.name);
  const t0 = Date.now();
  ctx.steps.push({ agent: agentName, tool: toolUse.name, input: toolUse.input });

  return withSpan(
    `execute_tool ${toolUse.name}`,
    {
      attributes: {
        'gen_ai.operation.name': 'execute_tool',
        'gen_ai.tool.name': toolUse.name,
        'gen_ai.tool.type': 'function',
        'gen_ai.tool.call.id': toolUse.id,
        'gen_ai.tool.description': tool?.definition.description,
        'gen_ai.tool.call.arguments': json(toolUse.input),
      },
      // The LLM's tool call output is this tool's input.
      links: chatSpan ? [flow(chatSpan, 'output', 'input')] : [],
    },
    async (span) => {
      const spanContext = span.spanContext();
      try {
        if (!tool) throw new Error(`Unknown tool ${toolUse.name}`);
        const output = await tool.handler(toolUse.input, ctx);
        const content = typeof output === 'string' ? output : JSON.stringify(output);
        span.setAttribute('gen_ai.tool.call.result', json(content));
        log.info(
          { event: 'tool.call', tool: toolUse.name, tool_input: toolUse.input, tool_ms: Date.now() - t0, status: 'ok' },
          `Tool ${toolUse.name} executed`,
        );
        return { spanContext, result: { role: 'tool', tool_call_id: toolUse.id, content } };
      } catch (err) {
        // Tool errors go back to the model as text, so record them without failing the request.
        span.recordException(err);
        span.setStatus({ code: SpanStatusCode.ERROR, message: err.message });
        log.error({ event: 'tool.call', tool: toolUse.name, tool_input: toolUse.input, status: 'error', err }, `Tool ${toolUse.name} failed`);
        return { spanContext, result: { role: 'tool', tool_call_id: toolUse.id, content: `Error: ${err.message}` } };
      }
    },
  );
}

function parseArgs(args) {
  try {
    return args ? JSON.parse(args) : {};
  } catch {
    return {};
  }
}

6Sessions and prompts

Sessions. Set gen_ai.conversation.id to one ID per conversation on every agent and model span (the sketch passes sessionId through). All turns of a conversation then group into one LLM Observability session. If you already pass a session ID to llmobs.trace(), reuse that value.

Prompt tracking (optional). To see calls, tokens and latency per prompt version, add the attribute _dd.ml_obs.prompt_tracking to each chat span: a JSON string with id, version, template (or chat_template) and variables. This repository builds it with a small helper:

backend/src/agents/prompts.js
// Versioned prompt templates, tracked in Datadog LLM Observability (Prompt Tracking).
// Every LLM span carries `_dd.ml_obs.prompt_tracking` (JSON: id, version, chat_template, variables),
// so LLM Observability groups calls per prompt and version, diffs versions and opens them in
// Playground. Bump `version` whenever a template changes.
// https://docs.datadoghq.com/llm_observability/monitoring/prompt_tracking/

/** Fills {{name}} placeholders from variables. */
export function renderTemplate(template, variables = {}) {
  return template.replace(/\{\{(\w+)\}\}/g, (_, name) => String(variables[name] ?? ''));
}

/** Value of the `_dd.ml_obs.prompt_tracking` span attribute for one LLM call. */
export function promptTracking(prompt, userMessage) {
  const variables = Object.fromEntries(Object.entries(prompt.variables ?? {}).map(([k, v]) => [k, String(v)]));
  return JSON.stringify({
    id: prompt.id,
    version: prompt.version,
    chat_template: [
      { role: 'system', content: prompt.template },
      { role: 'user', content: '{{user_message}}' },
    ],
    variables: { ...variables, user_message: String(userMessage ?? '') },
  });
}

8Verify

Local check
# The app logs one line per OTLP export batch (from otel.js)
grep '"event":"otel.export"' <your log file> | tail -3
#   status "ok"     -> spans reached Datadog
#   status "error"  -> 401/403: wrong API key or DD_SITE; network error: no egress to otlp.<site>:443

Send a request that makes the agent call at least one tool, wait 3–4 minutes, then in Datadog (replace app.datadoghq.com with your site):

  1. LLM Observability → Traces, filter @ml_app:<OTEL_SERVICE_NAME>, open a trace and click Execution Graph. You should see the agent, its model calls and tools, and any sub-agent nested under its hand-off tool.
  2. In the same trace, click View in APM. Your existing APM trace for the request opens, and its Logs tab shows the request's logs.
  3. Check that each model call appears once. Two copies mean dd-trace's LLM Observability is still on (step 1).

9Troubleshooting

SymptomCause and fix
No traces in LLM ObservabilityWait 3–4 minutes, then check the otel.export log lines. 401/403: wrong API key, or DD_SITE doesn't match your org. Network errors: the app has no egress to otlp.<site>:443.
Traces appear but there is no Execution Graph buttonThe spans have no links, or the trace came from dd-trace's LLM Observability. Check that DD_LLMOBS_ENABLED is unset and that every chat and execute_tool span gets its links.
The graph is missing edges, or a sub-agent floats on its ownA link is missing. Every model call after the first needs one link per tool result; a sub-agent must run inside its hand-off tool's withSpan, so that activeSpan() finds the tool.
Every model call appears twicedd-trace's LLM Observability is still on. Remove DD_LLMOBS_ENABLED everywhere it is set.
Agent, model and tool spans are split across several tracesA span was started outside the active context, for example in a callback that lost the async context. Create spans with withSpan (it uses startActiveSpan) and await inside it.
View in APM finds no traceThe LLM Observability trace ID must equal the dd-trace trace ID. Check that otel.js passes idGenerator: new DatadogTraceIdGenerator(), is imported first, and that the app still starts with --import dd-trace/initialize.mjs.
Each turn is its own sessionUse the same gen_ai.conversation.id for every turn of a conversation.
